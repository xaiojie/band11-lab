# 腕上桌宠 · 快应用方案（v1 思考稿）

素材来源：https://github.com/MerZlin/dsh-pet-indesktop（MIT），已 clone 到 `/Users/jay/开发/band11/pet_src`（263 MB）。
目标设备：小米手环 11（q66cn），212×520 / Vela QuickApp。

---

## 0. 一句话结论

做成**快应用**，不做表盘。

表盘 bin 只能承载静态图 + 有限控件（现有工具仅支持 pointer / imagelist / dignum / process 四种），
动画和 JS 都写不进去；快应用能跑 `setInterval` 换帧、能存亲密度、能调振动、能响应触屏。
代价是**不能常驻表盘**——每次要进应用列表点开。

### 状态机

| 状态 | 触发 | 行为 |
|---|---|---|
| `idle` | 默认 / 动作结束 | 循环播 idle 片段，8 fps |
| `react` | 点宠物 | 随机 1 个 click 反应，振动 `short`，亲密度 +1 |
| `eat` | 点「零食」 | 播吃的动画，亲密度 +3，饱食度 +1（每日上限 5 次） |
| `sleep` | 点「睡觉」/ 23:00–7:00 / 10s 无操作 | 播睡觉 loop，界面压暗 |
| `wake` | 点任意处 | 回 idle |

- 持久化：`storage` 存 `intimacy` / `fedToday` / `lastFedDate` / `lastOpen`（字符串 key-value）。
- 时间：`setInterval` 每 30s 对一次时钟，跨天重置 `fedToday`。

## 2. 素材管线（真正的工程量在这里）

源素材：106 个 640×360 / VP9 / 24fps / 10.042s（241 帧）/ **纯黑背景** 的 webm，无 alpha 通道。

处理链：

1. **抽帧**：`ffmpeg -vf fps=8`（idle）/ `fps=12`（反应类）→ PNG 序列。
2. **黑底抠像**：`alpha = clip((max(R,G,B) − 22) / 40, 0, 1)`，再**反解颜色**
   `color = stored / alpha`。黑底素材是预乘存储，不反解会让深蓝头发/衣服发灰变透明；
   反解后颜色准确，实测边缘干净无黑边。
3. **固定裁切**：按仓库 `manifest.json` 的 `body_box [212, 60, 428, 330]` 裁成 170×212。
   用固定框而不是逐帧 bbox，否则角色会在画布上抖动。
4. **调色板量化**：64 色 + alpha，PNG optimize。
5. **输出**：`assets/pet/<clip>/f_000.png…` + `common/pet_data.js` 描述表
   （clip 名、帧数、fps、是否循环、结束后转入哪个状态）。

**实测体量：6.2 KB/帧（170×212，64 色）**，不量化是 66 KB/帧（差 10 倍，必须量化）。

### 帧数预算

| clip | 帧数 | 约 |
|---|---|---|
| idle（3s 循环片段） | 24 | 149 KB |
| 摸摸 1 | 15 | 93 KB |
| 摸摸 2 / 生气 | 15 | 93 KB |

## 3. 渲染与性能

- **主路**：`setInterval` 换 `<image :src>`，8–12 fps。
- **兜底**：若真机掉帧，改「精灵条 + CSS transform」——但 Vela 的 `animation`/`steps()` 支持度没查到明确文档，需真机验证，不作为首选。
- **首帧**：FMP ≤ 2000 ms。首屏只渲染 idle 第 0 帧，300 ms 后再起 timer，其余 clip 懒加载。
- **内存**：同一时刻只保留当前 clip 的路径，切状态时旧 clip 不再引用。
- **省电**：`onHide` 停 timer；不申请网络权限。

## 4. 分期

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0（半天）** | 20 帧 idle 打进现有脚手架，真机跑 | 帧率是否够、清晰度、启动耗时 |
| **P1（1 天）** | 三按钮 + 状态机 + 亲密度存储 + 振动 | 点宠物有反应且不卡 |
| **P2（半天）** | 从 89 个 random 里挑 6–8 个做彩蛋 + 台词表 | 长时间玩不重复 |
| P3（可选） | 接 DeepSeek 余额 / 天气 | 需手机端 interconnect 桥接，复杂度高，先不做 |

## 5. 风险

1. **`setInterval` 精度/掉帧** —— 最大不确定性，P0 必须先验证；不行就换精灵条。
2. **不能常驻** —— 快应用不是表盘，不能抬腕即见。想要常驻只能做表盘，但表盘放不了动画。
3. **手环没有扬声器** —— 仓库里的 `assets/sounds` 用不上，反馈只能靠振动。
4. **素材授权** —— 仓库 MIT，但角色形象（shenshen）商用要谨慎；自用无碍。
5. **触屏区域小** —— 170×212 的舞台在 212 宽屏上，点击命中判定要放大到整块舞台。
